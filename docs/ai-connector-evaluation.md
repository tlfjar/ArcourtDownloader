# AI connector evaluation for issue #8

Evaluated on 2026-10-08 against the checked-out Go 1.26 modules and Go 1.27.1 on Windows/amd64. The application needs one local text-generation call to a user-selected provider, bounded request content, reported usage when available, explicit credentials, cancellation, and an injectable transport for offline tests. The optional SDK's image capability does not imply this feature sends images: the current naming workflow sends text only and falls back for image-only PDFs.

GoAI was selected because the tagged source has all four direct provider destinations without an installed gateway, its common API keeps the application-facing boundary small, and a Windows spike exercised all four actual request/response paths. Its xAI implementation is a distinct xAI provider wrapper over a protocol xAI documents as compatible; it is not a native xAI wire format. The [provider implementations](https://github.com/zendev-sh/goai/tree/v0.10.6/provider) and [generation options](https://github.com/zendev-sh/goai/blob/v0.10.6/options.go) were inspected at the pinned tag. The SDK also supports tools, file uploads, remote references, and traces; this feature invokes none of them.

## Compilable spike and dependency measurement

A temporary Go module outside the repository pinned `github.com/zendev-sh/goai v0.10.6`. A mock HTTP server received one request per provider and returned representative native responses. `GOWORK=off go run .` passed on Windows/amd64 with Go 1.27.1: OpenAI used `POST /v1/responses` and Bearer auth, Anthropic `POST /v1/messages` and `x-api-key`, Google `POST /v1beta/models/{model}:generateContent` and `x-goog-api-key`, and xAI `POST /v1/chat/completions` and Bearer auth. Each response yielded its expected label and 10 input / 5 output tokens. This verifies serialization and parsing against synthetic responses, not paid live model access or naming quality.

The standalone spike's module graph contained GoAI, `golang.org/x/oauth2`, `cloud.google.com/go/compute/metadata`, and test-only `go.uber.org/goleak`. A minimal Windows/amd64 Go 1.27.1 program using `net/http` was 5,393,920 bytes. A companion program importing all four providers and retaining `GenerateText` was 10,939,904 bytes, a 5,545,984-byte difference. This is an isolated spike measurement, not an ArcourtDownloader desktop binary size or an estimate of its exact release delta.

## Production adapter controls

The adapter in `arcourt/naming_provider.go` pins HTTPS port 443, provider host, method, and path before passing a request to its dedicated transport. It disables environment proxy discovery and redirects; the injected transport argument exists for offline tests. The explicit `:443` base URLs also prevent GoAI's optional `*_BASE_URL` environment fallback from replacing an otherwise default URL. A credential is supplied in memory and never placed in the request body. No court client, cookies, browser headers, optional tracing hook, tool, remote file reference, provider failover, or prompt-cache directive is used.

The adapter permits at most 2,048 bytes of system instruction, 4,096 characters and 8,192 bytes of excerpt, 16 KiB of the complete serialized outbound JSON body, 64 KiB of response body, and 96 output tokens requested from the provider. `RequestBytes` records the full serialized HTTP body, including SDK-added content, once it is allowed through the final boundary. Provider token counts are recorded only when returned with nonzero values; missing usage on errors remains unknown. `RequestBytes` after a transport failure records an attempted send, not proof of remote completion or billing.

The application passes a cancellation context. The adapter caps one HTTP call at ten seconds and explicitly sets `WithMaxRetries(0)` and one generation step. It maps auth, model, rate-limit and refusal responses into controlled reasons, without exposing provider error bodies. The complete naming workflow has its own twelve-second deadline and maximum of two transmissions across excerpt expansion. [Offline transport tests](../arcourt/naming_provider_test.go) cover all four endpoints and auth schemes, output limits, usage, refusal, error codes, no hidden retries, payload and response caps, redirect blocking, environment base URL isolation, proxy isolation, cancellation, and unknown usage after failed transport.
